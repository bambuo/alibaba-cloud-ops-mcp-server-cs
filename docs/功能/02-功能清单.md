# 02 功能清单

> 文档编号：02
> 状态：已实现，工具面与语义核对完成（云端返回待真实账号）
> 证据基线：上游 v0.9.27，commit 751a8fd（2026-10-27）；本仓库 commit 14f3821

## 一、统计口径

- 分母来源：上游 `src/alibaba_cloud_ops_mcp_server/tools/*.py` 中带 `@tools.append` 或 `_append_tool` 装饰器的函数 34 个，加上 `config.py` 驱动的动态 API 11 个。
- 默认模式跳过静态 `ECS_DescribeInstances`（`server.py` 显式排除），由动态工具提供同名能力，故默认面为 33 + 11 = 40。
- 不计入：未注册的 `OSS_PutObject`、`create_client`、`_start_execution_sync`、`_tools_api_call` 等内部函数。
- 复核命令（上游仓库）：

```bash
grep -rn "@tools.append\|_append_tool" src/alibaba_cloud_ops_mcp_server/tools/
grep -n "def OSS_PutObject" src/alibaba_cloud_ops_mcp_server/tools/oss_tools.py
```

- 验证等级（本仓库）：

| 等级 | 含义 |
|---|---|
| A | 本地通过 MCP 协议实际调用并断言返回 |
| B | 单元测试覆盖请求/返回构造，或本地构造层可复算 |
| C | 仅完成 schema 与源码逐项比对，未执行真实调用 |
| D | 依赖真实云账号，本地无法验证 |

## 二、总量与注册规则

| 模式 | 工具数 | 组成 |
|---|---|---|
| 默认 | 40 | 动态 11 + OOS 10 + CMS 9 + OSS 4 + LOCAL 3 + 部署 3 |
| 默认 + `--services` | 44 | 追加 PromptUnderstanding、ListAPIs、GetAPIInfo、CommonAPICaller |
| `--code-deploy` | 7 | 部署 3 + 静态 `ECS_DescribeInstances` + LOCAL 3 |

四种模式的 `tools/list` 实测数量与上游一致（40/44/7/3）。

## 三、动态 API 工具（11）

由 `config.py` 与 OpenAPI 元数据生成，鉴权均为 AK/SK；工具名格式 `{服务大写}_{API}`。

| 工具 | 上游 API | 功能 | 本地验证 | 状态 |
|---|---|---|---|---|
| `ECS_DescribeInstances` | ECS DescribeInstances | 查询实例列表 | B：schema 含元数据 37 个参数，`RegionId` 必填，`InstanceIds` 转数组 | 一致 |
| `ECS_DescribeRegions` | ECS DescribeRegions | 查询地域 | B：`RegionId` 默认 `cn-hangzhou` | 一致 |
| `ECS_DescribeZones` | ECS DescribeZones | 查询可用区 | B：`RegionId` 必填 | 一致 |
| `ECS_DescribeAccountAttributes` | ECS DescribeAccountAttributes | 查询账号配额属性 | B：`AttributeName` 转数组 | 一致 |
| `ECS_DescribeAvailableResource` | ECS DescribeAvailableResource | 查询可用资源 | B：2 个必填参数 | 一致 |
| `ECS_DescribeImages` | ECS DescribeImages | 查询镜像 | B：`Tag`/`Filter` 为数组 | 一致 |
| `ECS_DescribeSecurityGroups` | ECS DescribeSecurityGroups | 查询安全组 | B：`SecurityGroupIds` 转数组 | 一致 |
| `ECS_DeleteInstances` | ECS DeleteInstances | 删除实例（破坏性） | B：`InstanceId` 转数组，2 个必填参数 | 一致 |
| `VPC_DescribeVpcs` | VPC DescribeVpcs | 查询 VPC | B：`RegionId` 必填 | 一致 |
| `VPC_DescribeVSwitches` | VPC DescribeVSwitches | 查询交换机 | B：无必填参数 | 一致 |
| `RDS_DescribeDBInstances` | RDS DescribeDBInstances | 查询 RDS 实例 | B：`RegionId` 必填 | 一致 |

schema 生成规则与上游一致：跳过含 `.` 的参数；参数描述拼接 `参数类型` 与 `参数示例`；选填参数默认 `null`；ECS 的 `InstanceIds` 等 15 个列表参数在元数据类型为 string 时转 `array`；缺失 `RegionId` 时补 `cn-hangzhou`。

调用语义：按元数据决定 GET/POST、版本、路径与 style；查询参数中的空值剔除；ECS 列表参数序列化为 JSON 数组文本；`RegionId` 缺省回落 `cn-hangzhou` 并转小写；端点按服务/地域规则解析。

## 四、OOS 工具（10）

均通过 `StartExecution` 调用 ACS 公共模板，轮询 `ListExecutions` 到终态后返回其 `body`；`Failed` 抛 `OOSExecutionFailed`。上游无总超时，本实现固定 600 秒。

| 工具 | 模板 | 关键参数 | 本地验证 | 状态 |
|---|---|---|---|---|
| `OOS_RunCommand` | ACS-ECS-BulkyRunCommand | `targets` 含 `Parameters.RegionId` 与 `Status=Running`、`commandType`、`commandContent` | C：源码逐项比对 | 一致 |
| `OOS_StartInstances` | ACS-ECS-BulkyStartInstances | `regionId`、`resourceType`、`targets` | C：源码逐项比对 | 一致 |
| `OOS_StopInstances` | ACS-ECS-BulkyStopInstances | 追加 `forceStop`（参数名 `ForeceStop`） | C：源码逐项比对 | 一致 |
| `OOS_RebootInstances` | ACS-ECS-BulkyRebootInstances | 追加 `forceStop`（参数名 `ForeceStop`） | C：源码逐项比对 | 一致 |
| `OOS_RunInstances` | ACS-ECS-RunInstances | 21 个参数；空字符串选填项不传；`Tags` 转对象数组；`DataDiskParameters` 解析 JSON 数组后传入 | C：源码逐项比对 | 一致（描述文案差异） |
| `OOS_ResetPassword` | ACS-ECS-BulkyResetPassword | 追加 `password` | C：源码逐项比对 | 一致（描述文案差异） |
| `OOS_ReplaceSystemDisk` | ACS-ECS-BulkyReplaceSystemDisk | 追加 `imageId` | C：源码逐项比对 | 一致 |
| `OOS_StartRDSInstances` | ACS-RDS-BulkyStartInstances | `resourceType=ALIYUN::RDS::Instance` | C：源码逐项比对 | 一致（描述文案差异） |
| `OOS_StopRDSInstances` | ACS-RDS-BulkyStopInstances | 同上 | C：源码逐项比对 | 一致 |
| `OOS_RebootRDSInstances` | ACS-RDS-BulkyRestartInstances | 同上；模板名为 `Restart` 不是 `Reboot` | C：源码逐项比对 | 一致 |

`OosExecutor` 的 body 解包、`Failed` 与超时分支由 `CommonToolsTests` 覆盖（B）；首次轮询前固定等待 1 秒，上游为立即轮询后每 1 秒一次，属时序差异。

## 六、OSS 工具（4）

使用 OSS SDK 独立签名，鉴权走同一凭证链。上游返回 Python 对象字符串，本实现返回结构化 JSON，属已声明差异；本地不发起真实调用，验证等级 C。

| 工具 | 参数 | 行为 | 状态 |
|---|---|---|---|
| `OSS_ListBuckets` | `RegionId` 默认 `cn-hangzhou`、`Prefix` 可空 | 列出 Bucket；本实现按 `Prefix` 客户端过滤 | 一致（前缀过滤位置不同） |
| `OSS_ListObjects` | `BucketName`、`RegionId`、`Prefix` | `BucketName` 为空时抛 `Bucket name is required`；分页列出对象 | 一致（V1 `ListObjects` 对 V2 `ListObjectsV2`） |
| `OSS_PutBucket` | 追加 `StorageClass=Standard`、`DataRedundancyType=LRS` | 创建 Bucket；非法枚举值回落默认值 | 差异：上游非法值由 SDK 报错 |
| `OSS_DeleteBucket` | `BucketName`、`RegionId` | 删除 Bucket | 一致（返回结构改为 JSON） |

`OSS_PutObject` 在 `oss_tools.py` 中存在但没有注册装饰器，不暴露为工具；本实现保持不注册。

## 七、本地工具（3）

不访问阿里云，权限等同运行主机。

| 工具 | 功能 | 本地验证 | 状态 |
|---|---|---|---|
| `LOCAL_ListDirectory` | 列出目录，支持递归；返回 `path`、`items`、`count`，按名称排序 | A：实际调用返回 `a.txt` 在 `b.txt` 前，目录 `size` 为 `null` | 一致（错误文本带 `NotFound:` 前缀） |
| `LOCAL_RunShellScript` | 执行命令或脚本；`shell=true` 走 `/bin/sh -c`，`shell=false` 按 POSIX 规则拆分参数；默认超时 300 秒 | A：`echo` 成功、超时返回 `CommandTimeout`、`shell=false` 执行 `/bin/echo` 成功 | 一致（超时上限与错误文本不同） |
| `LOCAL_AnalyzeDeployStack` | 识别 27 个探针文件、包管理器、框架、运行时版本与 Docker 基础镜像 | A：`package.json` + `go.mod` 返回 `deployment_methods=[npm,go]`、`node>=20`、`go 1.23` | 一致（仅 `.python-version` 时本实现也会记录版本） |

## 八、代码部署工具（4）

默认模式注册 3 个；`--code-deploy` 模式额外注册静态 `ECS_DescribeInstances`。鉴权 AK/SK，依赖 OSS 与 OOS。

| 工具 | 功能 | 本地验证 | 状态 |
|---|---|---|---|
| `OOS_CodeDeploy` | 解析项目根目录、生成启动/停止命令、上传产物、创建应用/分组、打标、发起部署 | B：部署规则 30+ 单测；请求字段源码比对 | 差异见下 |
| `OOS_GetDeployStatus` | 查询分组状态，返回 `info`、`status`、`execution_id`、`deploy_execution_info` | B：源码比对 | 一致 |
| `OOS_GetLastDeploymentInfo` | 读取 `.code_deploy/application.json` | A：无状态文件时返回 `{"message":"No information found about the last deployment","info":{}}` | 一致 |
| `ECS_DescribeInstances`（静态） | 按显式实例 ID 查询；空列表报错 | A：空 `instance_ids` 返回 `InvalidParameter` | 一致 |

`OOS_CodeDeploy` 与上游的已知差异：

1. 上游创建应用时传空 `AlarmConfig`，本实现未传。
2. Bucket 用确定性命名 `app-{应用名}-code-deploy`，上游按标签复用或随机命名。
3. 上游逐实例检查标签后再补打，本实现直接对全部实例调用 `TagResources`（标签键值相同）。
4. Go 可执行文件启动命令末尾带 `|| true`，上游无该后缀。
5. 首次轮询前固定等待 1 秒，上游立即轮询。

## 十二、本地核对结论

- 工具面：默认 40、`--services` 44、`--code-deploy` 7、`--enable-local-tools false` 37，与 Java 侧逐项一致（stdio 实测）。
- instructions：2099 字符，与 Java 侧逐行相等且含结尾换行（实测）；`PROMPT_UNDERSTANDING.md` 逐字节相等。
- 传输：`stdio`、`streamable-http`、`both` 三种模式均可用；`both` 下 stdio 与 HTTP 同时握手成功（实测）。
- CLI：`--help` 退出码 0、`--code-deploy false` 分离值、`--oos-timeout-seconds`、`--meta-cache-ttl-seconds`、`--enable-local-tools` 均与 Java 行为一致（实测）。
- 错误契约：统一为 `{"Code","Message","RequestId"?}` JSON，错误码表与 Java 对齐。
- 真实只读联调：`ECS_DescribeRegions`、`OSS_ListBuckets`、`CommonAPICaller` 嵌套 `Tag` 展开均成功；`--headers-credential-only` 下 OSS 仍可用。
- 单测：132 项全部通过（含 21 项语义回归）。
- 未覆盖：写操作类云端调用（建桶、部署、实例生命周期）与 CMS 指标返回，等级 D；CMS 与部分 ECS 调用在核对时段两侧均遇网络超时，属环境问题。
- 本轮修正：嵌套参数按 openapiutil 展开、动态工具注入 RegionId 默认值并校验必填、元数据失败降级与 TTL/重试、OSS 严格枚举与分页、实例精确集合校验、部署桶按标签复用、落盘合并写、启动命令与描述原文对齐。
